## Обучение персонала без разрозненных файлов и ручного контроля

**AI-наставник 360** объединяет обучение сотрудника в Telegram и управление учебным процессом в web-панели. Сотрудник видит назначенные курсы, продолжает обучение с места остановки и отслеживает прогресс. Методист, руководитель и администратор работают с программами и назначениями через ролевой интерфейс.

В системе заранее разделены функции **наставника**, **конструктора заданий** и **экзаменатора**. AI помогает проводить обучение, но не принимает кадровые решения и не подтверждает квалификацию сотрудника единолично.

> **ДИС** — цифровой лис и маскот продукта. Он сопровождает сотрудника в процессе обучения и помогает ориентироваться в системе.

## 💼 Ценность для компании

| Задача | Как помогает AI-наставник 360 |
|---|---|
| Материалы и обучение находятся в разных каналах | Сотрудник проходит назначенную программу через Telegram |
| Руководителю сложно видеть ход обучения | Прогресс и статусы доступны в web-панели |
| Разные роли получают лишние полномочия | Реализовано ролевое управление доступом |
| AI одновременно учит и оценивает | Наставник и экзаменатор разделены архитектурно |
| Автоматизация влияет на кадровые решения | Финальная ответственность остаётся за человеком |

## 👥 Для кого создан продукт

- **Сотруднику** — проходить назначенные курсы в привычном Telegram-интерфейсе.
- **Методисту** — создавать и структурировать учебные программы.
- **Руководителю** — назначать обучение и отслеживать прогресс команды.
- **Администратору** — управлять доступом и контролировать работу системы.

## 🧭 Архитектурный принцип

```text
Сотрудник → Telegram-бот → сервис обучения → база данных
                                      ↓
Методист / Руководитель / Администратор → web-панель
```

Наставник, конструктор практических заданий и экзаменатор проектируются как независимые компоненты. Такое разделение позволяет отдельно управлять учебным контентом, критериями проверки и полномочиями участников.

Подробное описание: [docs/architecture.md](docs/architecture.md).

## 🚀 Быстрый запуск

### Требования

- Docker Desktop;
- Docker Compose;
- свободный порт `8000`.

### Запуск

```bash
cp .env.example .env
docker compose up --build -d
```

Миграции и демонстрационные данные создаются автоматически при запуске сервиса `web`.

После запуска:

- web-панель: [http://localhost:8000/login](http://localhost:8000/login);
- проверка готовности: [http://localhost:8000/health/ready](http://localhost:8000/health/ready);
- логи: `docker compose logs -f web bot`.

## ⚙️ Настройка окружения

Все доступные параметры перечислены в [.env.example](.env.example).

Основные переменные:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота |
| `LOG_LEVEL` | уровень журналирования, по умолчанию `INFO` |
| `SEED_ON_START` | создание демонстрационных данных при запуске |

Не добавляйте рабочий файл `.env` и реальные токены в Git.
